## L2 - Lists
### Abstract Data Types (ADT)
- Type defined in terms of its data items and associated operations, not its implementation
- Abstract Data Type (ADT) is a conceptual model. They define what a data structure does without dictating how it does it. By separating the logical properties from the physical implementation, ADTs allow for cleaner, more maintainable code.
#### Benefits of ADT Approach
- Code is easier to understand if different issues are separated into different places
- Client can be considered at a higher more abstract level
- Many different systems can use the same library, so only code tricky manipulations once, rather than in every client system
- There can be choices of implementations with different performance tradeoffs, and the client doesn't need to be rewritten extensively to change which implementation it uses
#### Challenges of ADT Approach
- Specify how to deal with boundary cases
	- Negative numbers
	- Double calls (e.g. reserve a seat thats already been reserved)
	- 0
- We can "adapt" existing ADT structure with our own inputs as well

#### Index-Based Lists (List ADT)
- An index-based list (usually) supports the following operations:
	- size() 
	- isEmpty()
	- get(i)
	- set(i, e) - returns value at i before e replaces
	- add(i, e) - shifts everything >= i up
	- remove(i) - shifts everything >= i down, returns value e

##### Array-Based List

- If array has size N then we can represent lists of size n<=N

## L4
### Binary Search Trees (BST)
A binary search tree is a binary tree storing keys (or key-value pairs) satisfying the following BST property:

> For any node v in the tree and any node u in the left subtree of v and any node w in the right subtree of v, key(u) < key(v) < key(w)

Note that an inorder traversal of a binary search tree visits the keys in increasing order.

![[Screenshot 2026-06-03 at 11.58.21.png]]

#### Deletion
1. has 2 external child: delete directly 
2. has 1 external child: replace the deleted node with child 
3. has 2 internal children: replace the deleted node with inorder successor, i.e. the left-most node in right subtree
#### BST Searching
Runs in O(h) time, where h is the height of the tree. Best case $h=logn$, worst case $h=n-1$ 

#### Range Queries
Are just restricted inorder traversal searches

### Rank Balanced Trees
Aim to maintain a balanced BST to gaurantee average of O(logn) search.

#### AVL Tree
Self balancing tree. Behaves exactly like a BST but every node has a a requirement:
$$|\text{height of left subtree}-\text{height of right subtree}| \le 1$$
If this is violated, the tree must fix this using rotations - trinode restructuring.
![[Screenshot 2026-06-03 at 12.09.04.png]]

Suppose we have an AVL tree storing n items then
- The data structure uses O(n) space
- Height of the tree O(log n)
- Searching takes O(log n) time 
- Insertion takes O(log n) time
- Removal takes O(log n) time

#### Tree Based Priority Queues (Heaps)
A heap is a **binary tree** storing (key, value) items at its nodes, satisfying the following properties:
1. Heap-Order: for every node m ≠ root, key(m) ≥ key(parent(m))
2. Complete Binary Tree: let _h_ be the height
	- every level i < h is full (i.e. there are $2^i$ nodes)
	- remaining nodes take leftmost positions of level h

**Min Heap** holds the minimum value at the root
**Max Heap** holds the maximum value at the root
Its height is at MOST log(n)

- Insertion: 1. Create a empty space after the "last node" for new node 2. Apply the heap-order property, i.e, if the node is smaller than its parent, swap
- Removal: 1. Swap the "last node" and the root 2. Apply the heap-order property

**Heap-sort** is the version of priority-queue sorting that implements the priority queue with a heap. It runs in **O(n log n)** time.

#### Hash Functions & Hash Table
We have a hash function h, which alwasy give the same answer for the same exact input, and is fairly efficient to computer - where h(x) is an input on a hash table.
![[Screenshot 2026-06-03 at 12.41.31.png]]

**Hash Function**
- Function h: K → [0, N-1] that maps keys from a given set K of size m to integers in a fixed interval [0, N-1]
- Typically, N is much much smaller than m 

**Hash Value**
- The integer h(x) is called the hash value of key x 

**Hash Table** 
- Consists of the hash function and the array (aka table) A of size N
- The cell A[h(x)] stores a pointer to the item (x, value)
- Each cell of A is sometimes called a bucket

##### Collisions
Two keys $x,y$ collide if $h(x)=h(y)$
###### Universal Hash Functions
Suppose the key set is K = [0, M] and we need a hash table of size N. Let H be a family of such hash functions. We say that H is 2-universal if picking h uniformly at random (UAR) from H yields (for all i ≠ j):
$$Pr[h(i) = h(k)] ≤ 1/N$$
**Fact**: Let h be a function chosen UAR from a 2-universal family H. Then the expected number of collisions for a given key with a set of n keys is at most n/N
**In other words**: If A has n keys, and k is a new key, we can expect k to collide with at most n/N of the keys already in the table 

When collisions happen we have 3 methods for dealing with them

###### Seperate Chaining
Each cell of the hash table points to a linked list with any duplicate values in there. Simple, but requires additional memory outside the table.
###### Linear Probing
Place the colliding item into the next available cell. Colliding items lump together. Searching involves starting at correct cell, and moving until you find the item. We have to add a value **DEFUNCT** to differentiate between empty cells and deleted items.
###### Cuckoo Hashing
Uses two hash tables and two hash functions. This allows every value 2 places, and if they collide on one table, then one will go to its alternative location.
If it cant go to its alternative location, it evicts the current item and replaces it cell. The evicted item then goes to its alternative location, and if there is another item there, it evicts it and the cycle continues untill all items are settled. We can however get eviction cycles.

This strategy tries to visit all vertices at distance k from a start vertex s before visiting vertices at distance k + 1:

#### Dijkstra's
May not work for negative weight edges
```python
def Dijkstra(G, w, s):
	# initialize algorithm
	for v in V do
		D[v] ← ∞
		parent[v] ← ∅
	D[s] ← 0
	Q ← new priority queue for { (v, D[v]) : v in V }
	
	# iteratively add vertices to S
	while Q is not empty do
	u ← Q.remove_min()
	for z in G.neighbors(u) do
		if D[u] + w[u, z] < D[z] then
			D[z] ← D[u] + w[u, z]
			Q.update_priority(z, D[z])
			parent[z] ← u
	return D, parent
```

Using a heap for the Priority Queue (PQ), Dijkstra's algorithm runs in **O(m log n)** time.
Fibonacci heap is a PQ that can carry out decrease key in O(1) amortized time. Using that instead we get **O(m + n log n)** time.

#### Minimum Spanning Tree (MST)
Given a connected graph G = (V, E) with real-valued edge weights $c_e$, a MST is a subset of the edges $T\subseteq E$ such that T is a spanning tree whose sum of edge weights is minimised.
![[Screenshot 2026-06-03 at 13.54.58.png]]

##### Properties
**Cut Property**: Let S be any subset of nodes, and let e be the min cost edge with exactly one endpoint in S. Then the MST contains e.

**Cycle Property**: Let C be any cycle, and let f be the max cost edge belonging to C. Then the MST does not contain f.

#### Prims Algorithm
Finds the MST of a connected, weighted, undirected graph
**Idea**:
1. Pick any starting vertex.
2. Put it into a set $S$, where $S$ means “vertices already included in the MST.”
3. Look at all edges leaving $S$, meaning edges with one endpoint inside $S$ and one endpoint outside $S$.
4. Choose the cheapest such edge.
5. Add that edge to the MST.
6. Add the new vertex to $S$.
7. Repeat until every vertex is in $S$.

```python
def prim(G, c):  
	u ← arbitrary vertex in V  
	S ← {u}  
	T ← ∅  
  
	while |S| < |V| do  
		(u, v) ← min cost edge such that u in S and v not in S  
		add (u, v) to T  
		add v to S  
  
return T
```

Always add the cheapest edge that connects the current tree to a vertex not yet in the tree.

Runs in **O(m log n)** time. When Fibonacci heap used it can be improved to **O(m + n log n)** time.
#### Kruskal's Algorithm
Finds the MST of a connected, weighted, undirected graph
**Idea**:
1. Sort all edges by increasing weight.
2. Start with an empty set of chosen edges $T$.
3. Look at the cheapest remaining edge.
4. If adding it creates a cycle, skip it.
5. If adding it does not create a cycle, add it to $T$.
6. Repeat until you have $n−1$ edges, where $n$ is the number of vertices.

```python title: Kruskal's Algorithm
def Kruskal(G, c):
    sort E in increasing c-value
    T ← ∅

    for each edge (u, v) in sorted E do
        if adding (u, v) does not create a cycle then
            add (u, v) to T

    return T
```

 Always consider the cheapest unused edge, but only add it if it does not create a cycle.

Runs in **O(m log m)**. Also written as **O(m log n)** as in a simple graph m is about at most $n^2$.
## L9
### Greedy Algorithms
A greedy algorithm builds a solution by making the best local choice each step without considering past choices.
Greedy = locally optimal choice -> hope for global optimum.
It's not always correct!
Generic Structure:
1. Sort/order input
2. For each element
	- if it improves solution - take it
3. Return result

#### Fractional Knapsack
Given a set $S$ of $n$ items, each having:
- $b_i$ : a positive benefit
- $w_I$ : a positive weight

**Goal**: Choose items with maximum total benefit of weight at most $W$. 
**Solution**: Pick item with highest value/weight ratio : $\frac{b_i}{w_i}$ to maximise value per unit weight.
**Algorithm**:
1. Compute value/weight for each item
2. Sort items in descending ratio
3. For each item:
	- take as much as possible
**Complexity**:
- Sorting: O(n log n)
- Total: O(n log n)

An exchange argument proves a greedy algorithm is optimal by showing that any optimal solution can be transformed into the greedy solution without making it worse.

#### Interval Partitioning (Scheduling)
**Problem**: Schedule lectures using minimum classrooms. No two overlapping lectures in the same room. Depth = max number of overlapping intervals. Minimum rooms must be $\geq$ depth.
**Greedy Strategy**:
1. Sort lectures by start time
2. For each lecture:
	- assign to earliest available room
	- if non available --> open new room
**Complexity**: O(n log n) - priority queue
Greedy is optimal because it never "falls behind"

#### Text Compression - Huffman Encoding
- Let C be the set of characters in X
- Compute frequency f(c) for each character c in C
- Encode high-frequency characters with short code words
- No code word is a prefix of another code word
- Use an optimal encoding tree to determine the code words
**Problem**: Compress text using fewer bits
**Suggestion**:
- Frequent characters --> short codes
- Rare character --> long codes
- Use prefix codes (A prefix code is a code such that no code-word is the prefix of another code-word)
- NOTE - number of bits for a character = depth of character in tree
**Greedy Strategy**:
1. Put all characters in a priority queue (by freq.)
2. Repeat:
	- remove 2 smallest
	- merge into new node
	- reinsert
3. Final tree = encoding

Essentially the most common items at the top of a binary tree, shortest prefix codes (0 for left, 1 for right), rare items near the bottom, longer prefix codes. 
**Complexity**: O(d log d) where d = num of characters
Greedy works because optimal trees always combine lowest freq. nodes first.

```python
def huffman(C, f):

	# initialize priority queue
	Q ← empty priority queue
	for c in C do
		T ← single-node binary tree storing c
		Q.insert(f[c], T)
		
	# merge trees while at least two trees
	while Q.size() > 1 do
		f1, T1 ← Q.remove_min()
		f2, T2 ← Q.remove_min()
		T ← new binary tree with T1/T2 as left/right subtrees
		f ← f1 + f2
		Q.insert(f, T)
		
	# return last tree
	f, T ← Q.remove_min()
	return T
```

Greedy heuristics are easy to design but they are not always
optimal. And when they are, small modifications of the problem
can render them suboptimal:
- 0-1 knapsack is hard
- if tasks/lectures have special needs the problem is hard
- if we use non-binary encodings, Huffman does not work
## L10/11
### Divide and Conquer
**Idea**: 
1. Divide
	If the input is small enough, solve it directly. Otherwise split the problem into smaller subproblems.
2. Recur/Delegate
	Recursively solve each subproblem. Assume the recursive calls correctly solve each subproblem
3. Conquer
	Combine the answers from the subproblems into the final solution

##### Examples
**Binary search** is the simplest divide and conquer algorithm example - already know it

###### Merge Sort
Given an unsorted array, return it in sorted order
**Algorithm**:
```python
def merge_sort(S):
    if |S| < 2:
        return S

    split S into left and right halves

    sorted_left = merge_sort(left)
    sorted_right = merge_sort(right)

    return merge(sorted_left, sorted_right)
```

**Divide, Recur, Conquer**
Divide:
- Split array into 2 halfs
Recur:
- Recusively sort each half
Conquer:
- Merge the two sorted halves into one sorted array

**Runtime**: O(n log n) time

###### Quick Sort
**Algorithm**:
1. Choose a pivot.
2. Partition the array into:
       elements less than pivot
       elements equal to pivot
       elements greater than pivot
3. Recursively sort the less-than and greater-than lists.
4. Join:
       sorted less-than list
       equal-to-pivot list
       sorted greater-than list

**Divide, Recure, Conquer**:
Divide:
    Pick a pivot and partition the array.
Recur:
    Sort the less-than and greater-than partitions.
Conquer:
    Concatenate the sorted pieces.

**Runtime**: Expected O(n log n) as random pivot

NOTE --> any comparison based sorting takes O(n log n) time

#### Maxima-Set / Pareto Frontier
**Problem**: Given a set of points in 2D, find all maximum points. A point is maximum is no other point is both to its right and above it. This is a Pareto Frontier
**Algorithm**:
Begins with preprocessing - sort points by increasing x-coordinates, break ties by increasing y-coordinate
**Devide, Recure, Conquer**:
Divide:
    Split the sorted array into left and right halves.
Recur:
    Find the maxima-set of each half.
Conquer:
    Merge the two maxima-sets.
	1. Find the highest point p in the right maxima-set.
	2. For each point q in the left maxima-set:
	       if q.y > p.y:
	           keep q
	       otherwise:
	           discard q
	3. Add every point from the right maxima-set.

Because the points are sorted, every point in the right half has larger x-coordinate than every point in the left half. Hence every point in the right maxima-set remains maximum in the whole set.
**Runtime**: O(n log n)

#### Integer Multiplication
**Problem**: Given two n-digit binary integers x and y, compute: $x\cdot y$
**Solution**:
```python
def multiply(x, y):
# base case
⋮
# recursive case
	let x1 and x0 be such that x = x1 2n/2 + x0
	let y1 and y0 be such that y = y1 2n/2 + y0
	first_term ← multiply(x1, y1)
	last_term ← multiply(x0, y0)
	other_term ← multiply(x1 + x0, y1 + y0)
	
	return first_term 2n + (other_term - first_term - last_term) 2n/2 + last_term
```

**Runtime**: Solves to $O(n^{\log_2{3}})$, which is slightly better than the niave approach of $O(n^2)$

The general rule of solving runtime complexity with recurrences is: T(n) = recursive work + non-recursive work

###### Examples
**Binary search:**
T(n) = T(n/2) + O(1) = O(log n)

**Merge sort:**
T(n) = 2T(n/2) + O(n) = O(n log n)

**Linked-list binary search:**
T(n) = T(n/2) + O(n) = O(n)

**Naïve divide-and-conquer multiplication:**
T(n) = 4T(n/2) + O(n) = O(n²)

**Karatsuba multiplication:**
T(n) = 3T(n/2) + O(n) = O(n^log₂3)


#### Master Theorem
This is a theorem for recurrences in the form:
> T(n) = aT(n/b) + f(n)

where: 
- a = number of recursive subproblems
- b = shrink factor
- f(n) = non-recursive work per level
You compare f(n) to $n^{\log_b{(a)}}$ --> think of it like the recursive branching cost
So the master theorem asks:
Which dominates?
1. Recursive branching?
2. Work done at each level?
3. Are they balanced?

**Step by step**
1. Put the recurrence into the form: T(n) = aT(n/b) + f(n)
2. Identify a, b, and f(n).
3. Compute: n^(log_b a)
4. Compare f(n) with n^(log_b a).
5. Choose the matching case.

| Comparison                   |   Case |                       Result |
| ---------------------------- | -----: | ---------------------------: |
| `f(n)` smaller than critical | Case 1 |         `T(n) = Θ(critical)` |
| `f(n)` same as critical      | Case 2 | `T(n) = Θ(critical · log n)` |
| `f(n)` larger than critical  | Case 3 |             `T(n) = Θ(f(n))` |
